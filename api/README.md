# QSOL-IMC WebGL1 API — explicit, retained, dependency-free

**Status:** experimental opt-in API at /api/webgl/index.js. No new runtime package, CDN, WebGL2-only feature, scene graph, virtual DOM, automatic camera, asset manager, global cache or lifecycle scheduler. The existing VANILLAJS Renderer remains unchanged.

The design is based on the source-owned Renderer, OPT-INV-001/OPT-INC-001 unchanged-input rules, and the observed retained-buffer opportunities in QSOLKCB/Ski-Shooter and QSOLKCB/CorpoWars3d. It is **not** a claim of universally faster FPS. It emits normal WebGL1 commands, subject to ordinary driver/compositor costs and GPU state semantics.

## Contract

The facade owns one WebGL1 context and a fixed XYZ/RGB interleaved vertex layout (six Float32 values, 24 bytes per vertex). It compiles a compact coloured-geometry shader pair using the same fog and clear colours as the reference renderer. It accepts Float32Array views directly, including subviews. Caller arrays are validated before GPU work, and a *separate exact Float32 snapshot* is retained for one current generation per mesh.

~~~js
import {WebGLAPI} from './api/webgl/index.js';
import {perspective,viewMatrix,multiplyMatrices} from './modules/math/index.js';

const gpu = new WebGLAPI(canvas);
const triangles = new Float32Array([
  -.8,-.8,0,1,0,0, .8,-.8,0,0,1,0, 0,.8,0,0,0,1
]);
const mesh = gpu.createMesh(triangles);
const vp = multiplyMatrices(
  perspective(Math.PI/2.6,canvas.width/canvas.height),
  viewMatrix([0,0,4],[0,0,0,1])
);
gpu.beginFrame({vp,fog:.003,pointSize:1});
gpu.draw(mesh);
gpu.endFrame();
// After the data changes: gpu.updateMesh(mesh, triangles)
// Dirty partial vertex range: gpu.updateRange(mesh, firstVertex, packedXYZRGB)
// Explicit cleanup: gpu.deleteMesh(mesh); gpu.dispose();
~~~

## Explicit API surface

| Method | Effect |
| --- | --- |
| new WebGLAPI(canvas) | Own WebGL1 context, fixed shaders, depth testing; fail if unavailable |
| createMesh(data,primitive='triangles') | Allocate GPU mesh with validated XYZ/RGB Float32 values; returns opaque owned handle |
| updateMesh(handle,data) | Check exact current Float32 bytes, skip if identical; allocate only on growth, otherwise bufferSubData |
| updateRange(handle,firstVertex,data) | Vertex-aligned partial update within live draw count; exact unchanged bytes are skipped |
| beginFrame({vp,fog=0,pointSize=1}) | Caller-owned 4×4 VP matrix, viewport and clear; cache identical uniforms and program/viewport bindings |
| draw(handle) | Draw only live vertices; never draw old tail values after shrink; only bind/point attributes when needed |
| endFrame() | Close explicit draw period |
| stats() | Caller-visible driver-call counters (not a GPU stopwatch) |
| invalidateState() | Reset API's WebGL binding/uniform caches after external context state modifications |
| deleteMesh(handle), dispose() | Explicit resource lifetimes; reject stale/foreign handles |

The API never compares mutable object identities or relies on lossy fingerprints to skip uploads. It compares all Float32 bits, including signed zero, before skipping, so a reused typed array that changed in place cannot fabricate an unchanged-input hit. The API explicitly rejects nonfinite data and values that overflow Float32. It does **not** skip CPU verification; O(n) byte comparisons and snapshot ownership consume CPU and memory and may be slower for continuously changing very large meshes. Use this facade when static/retained geometry and small dirty ranges dominate; benchmark real workloads before selecting it over the established Renderer.

GPU buffer capacity is retained up to the largest successful upload and never shrinks before deletion. The API doesn't keep old scene generations, unbounded caches or references to input arrays. Initial capacity and growth are exact requested bytes, not power-of-two. Empty updates change draw count to zero and do not publish a false draw. All rendering output is generated by the same interleaved vertex bytes.

**Atomicity boundary:** validation errors perform no GPU write; a failing upload does **not** claim GPU rollback. After buffer writes, the API checks the standard WebGL getError result, including non-throwing WebGL errors, before publishing the new CPU snapshot/count. On any signalled write error it marks the mesh dirty, forbids drawing it, and forces a full reupload of the last committed CPU snapshot before a subsequent partial patch. Failed full writes likewise require recovery, even if the next bytes appear unchanged. No automatic retry, context-loss substitution or silent software fallback is performed. Calling getError after each buffer write has a potential driver cost: this API deliberately prioritises correctness; high-frequency workloads should measure that cost against the reuse savings.

## GPU state ownership and scope

The facade expects exclusive GL-state ownership for a canvas. Its public gl reference is provided for readPixels/diagnostics, but any external mutations to program, buffer or vertex attribute state require explicit invalidateState() before the next frame. Mixing independent renderers on one context without coordination is unsupported. A lost WebGL context requires an application-led teardown/reinitialisation; no old handles are promoted into a restored context.

This initial API is **WebGL1 coloured triangles/lines/points only**, without textures, lighting, materials, instancing, uniform arrays, index buffers, compute, draw sorting, physics, model importers or asynchronous streams. A caller may assemble geometry from terrain, procedural effects or CorpoWars buildings and then supply the resulting packed vertex arrays; the terrain/ballistics donor modules remain separate and opt-in. In particular, neither existing FPS Lab rendering nor the preserved RTX5060TI-001 benchmark has been changed.

## Verification and performance discipline

Tests in tests/webgl-api.test.js use an independent mock GL buffer store to check exact raw Float32 draw bytes, no-op update reuse, growth/shrink/empty behavior, partial upload offsets, mutable views, failure recovery, program/uniform/viewport call counts, invalid input and stale handles. scripts/browser-webgl-api.js additionally uses real Chromium WebGL1 readPixels to check that a no-op update preserves pixels while changed geometry produces different pixels. Both are now exercised by the ordinary CI script and packaged browser suite.

~~~sh
node --test tests/webgl-api.test.js
node --test tests/*.test.js
node scripts/check.js
node scripts/build.js
~~~

Instrumentation counts calls and submitted API bytes, **not** physical PCIe transfer, GPU memory allocation, actual GPU milliseconds or end-user FPS. Quantitative performance claims require a separate, source-pinned hardware workload and baseline comparison. The RTX5060TI-001 archive remains immutable and independent.
