# Start here

You can begin without knowing the engine architecture. A browser is enough to
try the [published Creator Hub](https://qsolkcb.github.io/VANILLAJS/demos/creator-hub/).
For this change's new lesson, serve a checkout as explained in the [README](../README.md#run-the-labs).

A **module** is a reusable tool, such as movement, collision or sound. A **Game
Lab** is a working example showing several tools together. **Game logic** gives
those tools meaning: collision detects a hit; your rules decide whether it
costs health, opens a door or wins a match. Keep those rules in your game.

1. [Make your first moving scene](CREATOR_QUICKSTART.md). No code editing needed.
2. [Build a game](HOW_TO_BUILD_A_GAME.md). Choose a lab and add your own rules.
3. [Modify a data pack](HOW_TO_MOD_A_GAME.md). Use the adapter for that lab.
4. [Export and share](HOW_TO_EXPORT_A_GAME.md). Understand what the output includes.
5. [Troubleshooting](TROUBLESHOOTING.md). Recover from common failures.

The [Creator Guide](CREATOR_GUIDE.md) explains more tools. The
[Workbench reference](EDITOR_WORKBENCH.md), [code recipes](../BUILD_A_GAME.md),
[API](API.md) and [architecture](ARCHITECTURE.md) are the advanced layer.
[Agents start here](AGENT_GUIDE.md); people do not need to read engineering policy
before trying the lesson.

## Make a small complete 2D game

When you are ready for sprites, levels and game rules, open [Game Maker Lab](../demos/game-maker-lab/index.html).
Its [guided tutorial](GAME_MAKER_LAB.md) starts with an empty map or a playable
original example. Paint, place a player/exit, test and download a complete ZIP
for the supported platform-game rules. This is separate from the Workbench scene
format. [Understand the export](GAME_MAKER_EXPORT.md) before sharing your files.
