# OSS-GAME-REUSE-001 — Evidence-led VANILLAJS engine roadmap

**Implementation update, 22 November 2026.** [v3.1.0](https://github.com/QSOLKCB/VANILLAJS/releases/tag/v3.1.0) shipped P1–P6. The first conditional materials follow-up now has a [bounded implementation and creator lab for review](MATERIAL_001.md). The original research and sequence follow below.

**Review date:** 20 November 2026 (Australia). **Status:** proposed, not an implemented API, release or certification.
**VANILLAJS main inspected:** `ae0b594f006ec3c1add71574c830ddde9ff5fa66`, the owner-merged COCKPIT-002 / PR #137 commit.
**Scope:** the eight user-supplied discovery collections, individual high-value exemplars, existing VANILLAJS capabilities and a sequence of original, testable improvements.
**Policy:** Apache-2.0 core, native ES modules, no runtime npm/CDN/cloud dependency, deterministic bounded simulation, original art, browser and offline evidence, owner/Codex review before merge.

**Recommendation:** after fixing the HORIZON acceptance regression, implement **SENSE-001 — shared visibility, occlusion and target-perception contracts**. That connects the existing FPS, cockpit, RTS, navigation and combat systems without replacing any of their authoritative physics. Follow with guided-projectile/actor-contact integration, then streaming/LOD and tactical AI.

## 5. First implementation PR specification: SENSE-001

Create a small *pure* reusable module, not a second combat engine:

- `modules/sensing/index.js` (proposed API only): `createSightWorld({ blockers, targets })` or equivalent inert validated snapshot; `querySight(observer, options)` returns owned ordered target records (`id, distance, visible, occluderId, reason`). Exact geometry and tie rules must be documented before optimisation.
- `tests/sensing.test.js`: independently written brute-force oracle; random bounded seeded cases; blocked side, muzzle inside wall, observer inside wall, equidistant and duplicate IDs, huge/nonfinite values, accessor/sparse input, direction boundary equality, no state mutation.
- `demos/sensing-lab/`: **one** original map using the same query for a grounded FPS view, tactical squad overhead view and air/space camera target panel. Different cameras must not change authority.
- `docs/SENSING_API.md`: +Y up, -Z forward, SI metres, target/occluder budgets, numerical approximation boundaries and 3-view evidence.
- Zero imported external source, art, icon packs or audiovisual assets. Reference donor projects only in the provenance section.
- Default verification: `node --test tests/*.test.js`, `node scripts/check.js`, `node scripts/build.js`, `node scripts/verify-offline.js` plus real packaged Chromium and, where an existing source-bound witness is affected, required full browser execution.
- Benchmark: serial brute-force/geometry-index parity and retained-memory consumption before calling an optimisation a win. Native RTX 5060 Ti results must be separately measured on the owner PC; hosted browser results are **not** transferable.

**Definition of ready:** user-approved API and scope, exact main SHA, independently reviewed correctness boundaries; **definition of done:** green full required CI on exact PR head, smoke-test actual browser action, Codex/owner sign-off and explicit merge permission. Tags/releases are always separate owner decisions.

## 6. Provenance/rights decision tree

1. Freeze the exact Git SHA, source file path and blob hashes **before** studying a candidate implementation. A listing alone is not licensing evidence.
2. Verify the actual file's SPDX/LICENSE, notices, copied asset terms and any patent/trademark or original-game dependencies. Record a decision of **direct-copy eligible**, **clean implementation only**, **catalogue data only** or **no permission established**.
3. For any MIT/BSD-compatible **actual copied code**, preserve exact attribution and licence notice in `NOTICE` and document modified files. Do not conflate permissive licensing with an obligation to copy.
4. Keep GPL/AGPL and unknown-licence code out of Apache-2.0 core. Different implementations of broad, noncopyrighted gameplay concepts should be independently authored, without transplanting source, expression, game maps or audiovisual work.
5. Retain old test baselines, source-bound artefacts, hashes and historical claims. New revisions receive new receipts; do not rewrite or bless frozen history.
6. Avoid build-time npm, network imports, Docker, Kubernetes, foreign engines and optional tool dependencies unless explicitly justified and owner-approved.
