## Model and theorem scopes

Q16ECMA.lean defines Euclidean integer modulo 2^32 and the signed
projection with the 2^31 boundary. Theorems bound the output and
prove identity for already checked, exactly represented 32-bit
signed or unsigned **integers**.

The Lean model does NOT formalize IEEE-754 Number encodings,
NaN, ±Infinity, -0 representation, objects, strings,
ToNumber coercion, Math.imul, the floating division estimate,
radix correction loops or JS exceptions. A mathematical statement
over unbounded Int must not be interpreted as JS engine equivalence.

The pinned source's int32() and uint32() functions reject
out-of-domain numbers before arithmetic; they canonicalize -0
to +0. The new finite source-pinned conformance checks cover
that acceptance boundary against JS bitwise operations and an
independent BigInt reference for the PRNG.

## Important executed negative witness

The mathematical int32 projection maps 2147483648 to -2147483648.
However the production checked int32(2147483648) throws RangeError.
Similarly ECMAScript NaN | 0 yields 0 but int32(NaN) rejects NaN.

Therefore **unchecked ToInt32 is not equivalent to the checked
int32 API over all JavaScript values**. This is a documented
counterexample, not a bug in the checked API. The accepted
integer domain is essential to the refinement statement.
