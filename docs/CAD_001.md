## What is implemented

### Reusable rendering geometry — `modules/cad-geometry/index.js`

- `revolveProfile({profile,segments})`: own/copy a strictly increasing authored `[[radius,y], ...]` profile, revolve around +Y, assemble outward-wound triangles and true planar caps, and return a frozen XYZ/UV triangle stream.
- `createCADPrimitive({kind,radius,height,segments})`: concrete bounded `column`, `cone`, and `urn` presets. Editable radius (0.1–5 metres), height (0.2–10 metres), 3–24 sides. Outlines are original; this is an opt-in graphics primitive, not a physical object/collider.
- `cadMeshOBJ(mesh)`: generate a deterministic, source-attributed strict OBJ with at most 64 KiB text, at most 1,536 XYZ/UV vertices and triangle faces. The browser's WebCrypto SHA-256 hash of the **exact emitted UTF-8 bytes** is recorded by the existing Asset Foundry.
- `cadColorStream(mesh,[r,g,b])`: native Float32 packed XYZ/RGB triangle stream for existing VANILLAJS WebGL renderers. No new GPU renderer, runtime library or shader is introduced.
- Input record, dense profile arrays, nonfinite values and complexity bounds are validated before geometry generation. Functions own the output; camera/texture/physics state is not touched.
- No boolean CSG, arbitrary imported STL, 3MF, hollow vessels, fillet radius, UV seam weld guarantees, manifold proof or historical scene migration. "Urn" is a closed silhouette, not a hollow drinking vessel.

### Visual Editor: new **CAD Primitives** controls

The existing [Visual Editor](../demos/editor/index.html) adds an opt-in `CAD PRIMITIVES` section inside Asset Foundry. Choose shape, radius, height and facets and click **Generate & Place CAD**.

1. A pure native CAD primitive is generated and serialised to deterministic OBJ; WebCrypto signs the bytes locally.
2. The strict existing `asset-foundry.addMeshAsset` parser admits or rejects the result, with Apache-2.0 licensing metadata and a `sourceSha256` content digest. No schema change or bypass of `MAX_MESH_VERTICES` / 256 KiB project budget.
3. The editor creates a new ordinary root **static** entity and attaches the generated mesh using the existing `setPlacement` flow. The pivot and object spawn place its bottom on the editor ground plane.
4. The existing `viewport.createSceneVertices`, scene picking, Undo/Redo, asset library, project save/open, play preview and exported HTML continue to handle the result. The generated graphic is presentation only; physics still sees the original entity box until collision authoring is explicitly extended later.
5. Pending asynchronous hashing is abandoned if play begins, source scene/library changes or a new project/import takes over. No stale asset is silently attached to a different scene.

### Example

~~~js
import {createCADPrimitive,cadMeshOBJ,cadColorStream}
  from './modules/cad-geometry/index.js';

const urn=createCADPrimitive({kind:'urn',radius:1,height:2,segments:16});
const text=cadMeshOBJ(urn); // Strict, canonical local OBJ; no file/network fetch
const packed=cadColorStream(urn,[.4,.7,.8]); // Float32 XYZ/RGB triangles
~~~

The render geometry and visual editor are genuine first-party consumers. DabbleCAD itself runs with Node/npm, Three.js, WASM and Electron; **none of these are required** to use CAD-001 in VANILLAJS.

## Acceptance/evidence boundaries

~~~sh
node --test tests/cad-geometry.test.js
node --test tests/*.test.js
node scripts/check.js
node scripts/build.js
node scripts/verify-offline.js
~~~

The new source-bound `.github/workflows/cad-lab.yml` executes the focused Node tests, source checks, offline build and real hosted Chromium editor smoke with one untouched Playwright browser dependency isolated in the CI runner's temporary folder. It must verify:

- Actual "Generate & Place" click creates a visible mesh and a new editable scene entity.
- Strict generated OBJ passes unchanged Asset Foundry parser and rendered Float32 geometry; project export/import preserves SHA-256/source licence and mesh/placement references.
- Undo/redo restore placement history without mutating mesh source or historical editor snapshots.
- Invalid inputs and play-mode conditions fail closed; the browser requests no external resources.
- Exact screenshots, browser SHA evidence, Node test summaries, and full source-bound Flight Lab verification must be recorded separately.

Tests independently check facet count, winding, caps, area, mesh budgets, deterministic OBJ byte equality, native packed-RGB parity and 120 seeded parameter sets. Hosted SwiftShader is **not** a physical RTX native-GPU p50/p95 measurement; no cross-platform visual or floating-point bit-exactness is promised.
